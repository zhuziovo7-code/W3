# 考场考生行为识别（W3 精简版）

这是考场行为识别项目的精简展示仓库，保留核心代码流程、关键配置和阶段性实验结果，不包含原始考场数据、大型模型权重、缓存特征或完整视频报告。

## 项目目标

系统从考场视频中检测人员，区分考生与监考员，并识别考生的九类行为：

1. 正常行为
2. 举手
3. 左右偏头
4. 传递可疑物品
5. 手放桌下并低头
6. 捡可疑物品
7. 携带手机
8. 撕卷子
9. 考生站立

## 核心流程

```text
视频/图片
  ↓
RTMDet 人体检测
  ↓
人体 ROI 特征提取
  ├─ 身份分类头：考生 / 监考员
  └─ 图像行为分类头：九类考生行为
  ↓
RTMPose 人体关键点与 PoseMLP 行为概率
  ↓
图像概率 + 姿态概率 + 几何规则融合
  ↓
IoU 多目标跟踪与连续帧确认
  ↓
行为结果、异常事件和可视化视频
```

纯 ROI 方案只使用人体区域图像特征；混合方案增加姿态关键点与时序规则，用于抑制单帧误报。

## 本次工作（by zjs）

本次实验聚焦于 ROI 图像行为分支的数据增强：

- 保留原图，并为训练集生成随机增强副本；
- 支持翻转、旋转、缩放、平移、亮度、对比度、饱和度、模糊和噪声；
- 使用多个 GPU 分片提取 RTMDet ROI 特征；
- 合并特征分片后，只重新训练九类行为分类头；
- 原学生/监考员身份分类头保持不变；
- 使用纯 ROI 与 ROI+Pose 混合方案完成整段视频推理对比。

对应代码位于 `scripts/zjs_*.py` 和 `scripts/zjs_run_rtm_roi_heads_pipeline.sh`。

## 当前实验结果

### 静态验证集

| 模型 | 平衡准确率 |
|---|---:|
| 原 ROI 行为分类头 | 94.59% |
| ZJS 图像增强 ROI 行为分类头 | 96.05% |
| 原 ROI+Pose 行为模型 | 97.45% |

ZJS 增强模型使用 26,114 份训练特征和 1,642 份验证特征，最佳模型来自第 32 轮。

| 行为 | 验证集召回率 |
|---|---:|
| 正常行为 | 87.20% |
| 举手 | 97.39% |
| 左右偏头 | 93.86% |
| 传递可疑物品 | 98.96% |
| 手放桌下并低头 | 97.06% |
| 捡可疑物品 | 97.32% |
| 携带手机 | 94.31% |
| 撕卷子 | 98.36% |
| 考生站立 | 100.00% |

### 完整视频对比

测试视频共处理 7,803 帧，得到 51,927 个考生框和 14,674 个监考员框。

| 推理方案 | 确认异常框 | 出现异常的帧 | 推理速度 |
|---|---:|---:|---:|
| 纯 ROI | 16,258 | 7,060 | 12.41 FPS |
| ROI+Pose 混合 | 10,715 | 5,603 | 8.20 FPS |

混合方案比纯 ROI 少输出 5,543 个异常框，但完整视频尚未制作逐事件人工真值，因此上述数量只能说明模型输出倾向，不能直接解释为准确率或误报率。

详细九类行为判定依据与效果见 [`docs/考生九类动作总结（by zjs）.xlsx`](docs/考生九类动作总结（by%20zjs）.xlsx)。

## 环境与运行

推荐 Python 3.10、PyTorch、MMDetection、MMPose 和 OpenCV。依赖范围见 `requirements.txt`。

模型权重和训练数据未上传。运行前需要按 `models/README.md` 放置外部预训练权重和本项目行为权重，并准备相应 JSONL 数据清单。

一键运行 ROI 图像增强训练：

```bash
NUM_SHARDS=4 \
PATH_MAP="旧路径前缀=当前数据根目录" \
bash scripts/zjs_run_rtm_roi_heads_pipeline.sh
```

各 Python 文件均支持 `--help` 查看详细参数。

## 结果使用限制

- 第五批数据由原图裁剪成多个网格小图，现有训练、验证和测试划分中存在同源裁剪重叠，因此验证指标可能偏高。
- 一部分困难样本只有 JSONL 标注，缺少原始图片，未完整参与本次重训。
- 真实视频尚缺逐事件人工标注，下一阶段应报告事件级 Precision、Recall、F1、每小时误报数和报警延迟。
- 本仓库仅用于代码流程和阶段性结果展示，不包含隐私数据或可直接部署的完整权重包。
